### New script: `scripts/check-desktop-css-overrides.mjs`
**Follows existing conventions**: `.mjs`, ESM, no shebang, `import.meta.dirname`, `process.exit(1)` on failure.

**Behavior**:
1. Reads all `.css` files under `apps/desktop/src/renderer/styles/features/`
2. Strips comments, then extracts each CSS rule's selector
3. Identifies "bare" selectors (no parent scope, no `:root[data-theme="dark"]`, no `:root[data-reduce-motion]`, no pseudo-class/pseudo-element)
4. Flags any bare selector that appears in >1 rule in the same file
5. Has a small inline allowlist for known unavoidable duplicates with a documented reason
6. Exits 0 if clean, 1 if new duplicates found (printing file/line details)

**Allowlist** (initially empty after cleanup, may have 1–2 exceptions):
- None expected after consolidation, but the allowlist exists for deliberate future exceptions

### Package.json changes
Add: `"desktop:css:check": "node scripts/check-desktop-css-overrides.mjs"`

### Validation
1. `bun run desktop:css:check` — must exit 0
2. `bun run desktop:typecheck` — must pass (only CSS and scripts touched)
3. Manual CSS review: confirm selector values produce same visual output by inspecting final consolidated values against the original tail-block values (they should match since we're preserving source-order-winning values)

### Edge cases and non-goals
- Not consolidating `.workflow-page .foo` scoped selectors — those are legitimate context overrides
- Not consolidating `:root[data-theme="dark"]` blocks — those are intentional theme variants
- Not refactoring the CSS structure (e.g., no CSS custom property extraction, no selector shortening)
- Not adding mobile adaptations or changing visual intent

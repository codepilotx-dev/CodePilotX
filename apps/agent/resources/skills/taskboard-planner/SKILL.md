# 任务看板规划

把用户的目标沉淀为可由用户持续跟踪和验收的任务。任务不是每个 Turn 的副本；只创建需要长期跟踪的工作成果。

## 开始方式

每次调用先用 `request_user_input` 询问用户希望：

- 创建一个完整任务；或
- 拆分为多个可独立验收的任务。

仅当目标、交付物或验收标准缺失且无法从上下文可靠推断时，再提出不超过三个简短问题。不要为了填满字段询问负责人、开始日期、截止日期、标签、子任务或任务关系；这些并不是当前创建工具的可靠输入。

如果当前会话没有项目上下文，说明任务必须属于项目，请用户先在 Working 中选择项目。此时不要调用 `taskboard_create`。

## 规划预览

在创建前展示全部任务的预览。每一项包含：

1. 标题：简短、面向结果。
2. 优先级：仅在用户明确给出时设置；否则使用 `none`。
3. 描述：目标、交付范围、验收标准和已知约束。多个任务时，还要写明建议执行顺序。

不伪造日期、标签 ID、负责人、任务关系或子任务。多个任务可在描述中说明依赖或建议顺序，但不要声称已建立系统关系。

预览后，用一次 `request_user_input`询问用户是否创建**全部**任务。用户取消、拒绝、要求调整或没有明确确认时，绝不调用创建工具。

## 创建与结果

用户明确确认后，按预览顺序逐个调用 `taskboard_create`：

- 传入标题、结构化描述和优先级。
- 不传标签，除非用户提供了已知有效的标签 ID。
- 新建任务自然进入 `backlog / 待立项`；不要尝试自动开始、完成或关联当前会话。

第一个创建失败时立即停止。不要重试、不要改变原计划后重放，也不要重复已成功创建的任务。最终清楚列出：

- 已创建任务，以及工具返回的编号或 ID；
- 由于失败尚未创建的任务；
- 安全的失败原因和下一步建议。

创建成功后简短说明这些任务位于当前项目的“待立项”，用户可从任务看板继续安排。

## 权限与外部 Agent

用户对预览的确认只确认业务意图，不能绕过 CodePilotX 的工具审批或权限策略。遵循系统给出的审批结果。

未来外部 Agent 通过 CLI 创建任务的预留说明位于 `references/external-agent-cli.md`。当前版本尚未提供该 CLI；不要执行、模拟执行或宣称它已经可用。
